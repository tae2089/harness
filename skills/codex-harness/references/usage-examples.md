# Request Routing Examples

The meta-skill builds or changes a harness. A generated harness executes its domain work. Ordinary questions or focused edits do not require rebuilding a harness.

| Request | Action |
| --- | --- |
| Build an SSO Codex harness | Define architecture/implementation/review roles, generate agents, skill, and AGENTS.md |
| Build a document-review harness | Define analysis and review responsibilities and verifiable document outputs |
| Build a competitor-research harness | Use independent researchers and a synthesizing analyst |
| Build a migration harness | Define bounded file ownership and integration checks |
| Build a full-stack harness | Main delegates decomposition and then spawns implementation workers |
| Build an incident-response harness | Define investigation and operational boundaries with existing approval rules |
| Add a security reviewer to this harness | Update the relevant role and review procedure only |
| Resume or revise previous work | Use the generated harness; read work records and inspect current artifacts |

For actionable work, preserve an explicit existing/new/no-issue choice; otherwise ask once. An issue URL is optional. Do not infer a publication destination from the request's domain or the Git remote.

For a fresh build, generate only the requested role TOMLs, the orchestrator skill with its three runtime references, and the project instruction sections. For an extension, follow expansion-matrix.md. For execution, follow orchestrator-procedures.md.

Non-triggers: explain a function, locate a file, summarize an existing document, or change an ordinary code line. These are not requests to create a new harness.
